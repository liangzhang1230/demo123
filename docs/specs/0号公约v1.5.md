# 【2】全局数据类型规范（五个最高频裁量点，全部没收）

| 类型 | 规范 |
|---|---|
| **金额** | 存储与运算一律"分"（int）；展示转"元"、千分位、默认整数元（¥12,480）；万元展示保留 1 位（3.5 万） |
| **比率** | 存储 0–1 小数；展示 ×100 保留 1 位（35.0%）；构成比展示为整数比（25 : 65 : 10） |
| **日期** | `YYYY-MM-DD`；月份键 `YYYY-MM`；周期比较一律左闭右闭 |
| **ID** | `{实体缩写}_{毫秒时间戳}_{4位随机}`，如 `deal_1721180000000_a3f9` |
| **舍入** | 金额入分、比率入 0.1%；**舍入只在展示层，运算层链式计算永不中途舍入** |

# 【3】兜底铁律（全局唯一实现）

```ts
safeDiv(a, b) { return (b === 0 || b == null || a == null) ? null : a / b }
// 每个指标声明 minSample；样本量 < minSample → 返回 null
// 前端对 null 的唯一渲染 = "—"（tooltip：样本不足）
// 🔴 全系统禁止上屏：Infinity / NaN / 负百分比 / undefined / 除号绕过 safeDiv
// 🔴 null ≠ 0：证据缺失必须显"—"，绝不退化为 0 参与判定（见 A-19）
// 🔴 时钟注入（C-14）：today 一律作为显式参数传入含日期的计算函数；计算层禁止直接调 new Date()，
//    UI 层唯一一处取真实时钟并下传。自检套件必须注入固定 TEST_TODAY（及 targetYear 等时间参数）；
//    对拍断言禁止依赖真实系统时钟——凡含日期的对拍，逐条写明注入值（发版检查 R-11）。
```

# 【4】宪法函数（唯一源，各板块 import，禁止重复实现）

## 4.1 totalIncome（员工视角"我拿到多少"）
```ts
totalIncome(spId, period) =
    底薪
  + 提成（M2 自动计算，margin_based 口径，见 4.5）
  + 奖金类 PayoutEntry（instant_bonus / year_end_bonus / dividend
                        / mentoring_share / recipe_royalty / sprint_vested / discretionary）
// 🔴 报销(reimburse)永不计入收入；VSA 冲刺金 vested 之前不计入
// 调用方：剪刀差、守护线、灯塔自动模式、钱途页、流失价签参考、参照点账本(M37)
```

## 4.2 laborCost（老板视角"我花了多少"）
```ts
laborCost(spId, period) =
    底薪 + social_cost（= 底薪 × socialCostRate） + 提成
  + 奖金类 PayoutEntry + 报销类 PayoutEntry   // 报销只进成本
// 回本公式 = 累计 laborCost + 期初 hiring_cost
```

## 4.3 netContribution（经营净贡献）
```ts
netContribution(scope, period) =
    毛利（Σ 回款 × 品类毛利率）
  − Σ laborCost
  − 自定义经营成本项（按天摊）
  − 退款毛利冲减（RefundEntry × 品类毛利率）
  − 折扣毛利泄漏（DiscountEntry × 品类毛利率）
// 页面固定注："经营净贡献，非财务报表口径"；目标准确率 90%
// 退款口径：不红冲、不对照原单、不倒扣提成；报表两层=原始累计回款 / 核算营收
```

## 4.4 leverageChain（全系统唯一分解口径）
```ts
净贡献 ≈ 线索量 × 转化率 × 客单价(aov) × 毛利率 − laborCost
// 线索量←日报/派单；转化率←计数制；aov = 累计核算营收 ÷ 累计成交笔数
// 同时是 M32 UER 的回归基础
```

## 4.5 提成口径（护城河，写进宪法）
```ts
commission = round(回款额 × 品类毛利率 × r)   // 🔴 margin_based，永不可换
// 全系统禁止出现统一毛利折算系数（如 G=0.6）
```

## 4.6 回算引擎核心（定价器心脏，公约级公式）
```ts
提成缺口 = T × (1 − 长期占比) − B
r        = safeDiv(提成缺口, G)          // 毛利口径
长期月度应得 = T × 长期占比               // → 分红池
// 边界守卫：B ≥ T×(1−长期占比) → 拦截"底薪已吃穿现金目标"；G ≤ 0 → 拦截
好招指数 = min(拟定B ÷ 预警档B, 拟定T ÷ 预警线T)
//  <1.0 🔴 ｜ 1.0–1.2 🟡 ｜ 1.2–1.4 🟢 ｜ ≥1.4 金
```


**为什么是"对冲"而不是"禁用"（设计原理，五板块话术同源）**

1. **病根不是"给了钱"**，而是：**当公司里所有值得做的事都明码标价，"没标价的事"就自动等于"不值得做的事"。** 员工会完成一次翻译——"冲大单原来是额外有赏的事，那没赏的事就是不用干的事"。（📎 Gubler-Larkin-Pierce 2016 Org Sci：象征/物质奖励挤出骨干 −8%；📎 Heyman & Ariely：小额金钱把社会规范切换成市场规范；📎 Gneezy & Rustichini 2000《A Fine Is a Price》：罚款取消后行为不回弹——**切换不可逆**。）
2. **豁免的理由是"无可挤出"**：`first_deal` 面向新人——他对"开单"尚无内在动机，此时给赏不是**替换**动力而是**制造**动力；`hire`（入职赏）面向招聘者养蓄水池，本属纯苦活。
3. **对冲的实质不是少给钱，是必须同时留一条不给钱的承认路径**。静默认可通道回答那个致命问题——"没赏的事还值不值得干？"值得，因为**长期干得好通向的是产权与台阶（M28 / 前程合约），不是奖金**。
4. **为什么这条对本系统尤其要紧**：全系统立身于第四定理（Hart 2016 诺奖）——你不给他控制权，他就不会投入那些你**测不到**的努力。而"测不到的努力"（带徒弟留不留一手、关键客户录不录进系统、难单接不接）**永远无法用悬赏购买**，因为测不到。静默认可通道是全系统**唯一**能承认这部分努力的地方。
5. **一句话**：**不是"不许用钱"，是"不许只有钱"。**

🔴 **禁用为何是错的**：v1.2 时代 4号 写"结果类→拦截保存"、5号 YE-04 五模板却全为结果类——两者同时成立时悬赏模块一个模板都存不进去，等于取消功能。实证支持的是"对冲后可用"，不是"禁用"。

# 【7】板块间数据交换信封（"合并成整体系统"的技术定义）

## 7.1 信封 schema（🔧C-05 新增 `derived{}` 块）

```json
{
  "schema": "skab_v1",
  "board": "dingjia | zhaoren | suanzhang | liuren | yuren",
  "exportedAt": "YYYY-MM-DD",
  "dataVersion": 1,
  "coefficientsHash": "系数表指纹（导入时校验一致性，不一致→提示同步，不阻断）",
  "derived":  { "派生标量名": 值, ... },
  "entities": { "实体注册表英文名": [ ...记录数组 ] }
}
```

🔴 **`derived{}` 存在的理由**：`realP90Factor` / `ahc` / `dvi` / `coachingDoseActual` 这些是**跨板块消费的派生标量**，不是实体、无法塞进 `entities`。v1.1 schema 只有 `entities`，导致各板块只能往顶层私自加字段（事实违规）。本版正式收编：**派生标量一律进 `derived`，实体一律进 `entities`，第三种位置不存在。**

**通用规则**：①各板块"导出数据包"产出此信封；②"导入"只认此信封，未知实体/未知 derived 键**静默跳过**（向前兼容）；③`dataVersion` 不匹配走公约迁移函数升级，**禁止报错拒收**；④表A 全部实体（含 🟤 埋设）从第一天就在信封白名单内——**这就是"表结构第一天埋"的技术落点**；⑤导入方以 `ExternalRef` 整条覆盖存储，**只读**（A-20）。

# 【11】🆕 授权与降级（C-12 · 单机版收费机制，五板块统一实现）

> **为什么在公约**：五个板块必须用同一套授权逻辑与同一套降级行为，否则客户买了三个板块会看到三种到期表现。**这是跨板块规则，按两级架构必须落在公约。**

## 11.1 机制（🔴 全程零网络请求，A-17 一字不改）

```
签发（作者本地，离线，🔴 C-13 私钥永不离开作者电脑）：
  payload = { tenant:"客户名", board:"dingjia|zhaoren|suanzhang|liuren|yuren", expiry:"YYYY-MM-DD" }
  sig     = ECDSA_P256_Sign(privateKey, payload)     // WebCrypto 同源算法，离线签发
  code    = BASE32( payload || sig )
  形如：SKAB-DJ-王总-20270718-A3F9C2E1…

校验（HTML 内，离线，crypto.subtle.verify——浏览器原生，零 CDN）：
  1. 解码 → 用内置 publicKey 验签 → 失败即无效（🔴 HTML 内只有公钥，拿到文件也无法伪造签名）
  2. 今天 > expiry            → BUILD_MODE = 'free'（降级）
  3. localStorage 记录 seenMaxDate；系统日期 < seenMaxDate → 锁定（防调表）
  4. 通过                     → BUILD_MODE = 'full'
续期 = 作者发新码，客户粘贴。零网络。
```

## 11.2 四条设计约束（缺一不可，机检）

| # | 约束 | 理由 | 机检 |
|---|---|---|---|
| **授-1** | 🔴 **署名可见**：授权客户名固定显示于**每一屏页眉**与**每一份打印报告页脚**（"授权：{客户名}"） | 文件可被整份转发，但转给同行 = 同行的方案书上印着你客户的名字。**社会防护 > 技术防护** | DOM + 打印模板断言 |
| **授-2** | 🔴 **到期只降级，不锁数据**：expiry 后回落 free（钩子屏可见、明细 .locked），**【7】信封导出功能永不锁定** | 不绑架客户，客户才敢买；也是最好的续费理由 | 单测：expiry 过期后导出仍可用 |
| **授-3** | 🔴 **不做机器绑定、不采集设备指纹** | 沾了就破坏"数据不出你电脑"的人设，且与 A-01 精神冲突。**宁可少防一点** | grep 无设备/浏览器指纹 API |
| **授-4** | 🔴 **降级不删数据、不改数据**：free 模式只影响渲染与功能可见性，localStorage 内容一字不动 | 重新续费即完整恢复 | 单测：降级前后 localStorage 快照一致 |
| **授-5** 🆕 | 🔴 **非对称验签（C-13）**：HTML 内唯一密钥材料 = 公钥；全码不存在 HMAC / 对称密钥 / secretKey | 对称密钥随包分发 = 把签发权交给每个买家（可给任意客户/板块/日期开码，授-1 随之失效）；公钥验签把伪造成本从"读源码"抬到"破解 P-256"。边界自知：本条拦"伪造授权码"，不拦"手改 JS 翻 BUILD_MODE"——后者的真防线是授-1 署名 + 年度系数包续费价值 | grep 无 HMAC/secretKey + 代码评审 |
