# 销售个人版 · 公司筛选器 —— 详细方案文档 v1.0

> 定位一句话：**把 HR 嘴里那个热乎乎的饼，翻译成一个冷冰冰的期望值，并自动亮红灯。**
> 从「找工作」到「该不该留」，一个纯前端单文件工具，帮销售个人少走弯路。

---

## 1. 目标用户与场景

| 用户 | 场景 | 对应模块 |
|---|---|---|
| 正在找销售工作的人 | 拿到一个 offer，HR 说「做得好月入 3 万」，不知真假 | 找 |
| 手上有多个 offer 的人 | 两三家在纠结去哪个 | 选 |
| 已在职、想跳槽的销售 | 现在这家还留不留？裸辞会不会更惨？下家到底行不行 | 留 |

**核心洞察（产品立足点）**：求职者入职前拿不到公司内部数据，能输入的只有 JD / 面试 / 聊天里给的那几个数字。所以本工具**不假装「看透公司内部」**，而是**把招聘方给出的承诺做压力测试**，算出真实期望值并识别陷阱。

## 2. 设计铁律（继承企业版，不可违背）

1. **金额一律以「分」为内部单位**，只有显示层转「元/万」；一切除法只走 `safeDiv`，除零/无数据返回 `null`。
2. **`null` ≠ `0`**：证据不足显示「—」，**绝不假装算出一个 0 或一个数**。这是信任的生命线——尤其「练」这类没有数据支撑的功能，宁可不给数，也不能编。
3. **判断只基于用户自己输入的数字**，**永不建立「公司名黑名单/评价库」**（名誉侵权红线）。
4. **数据只在用户本机 localStorage**，不上传服务器（隐私是卖点，也是护身符）。
5. **工具只给参考，永不替用户做决定**；每份报告底部固定免责声明。
6. **时钟注入**：纯计算函数不调用 `new Date()`，`today` 显式传入（便于自检回归）。
7. 计算层是**纯函数引擎**（可 Node 跑自检），UI 层只做 `innerHTML` 渲染——与企业版同构，方便直接搬公式。

## 4. 模块① 找 —— 单 Offer 冷静评估器（MVP 核心）

### 4.1 输入清单（极简，全部来自 JD / 面试）

| 字段 | 类型 | 说明 | 用途 |
|---|---|---|---|
| 城市档 cityTier | 枚举 tier1/tier2/tier34 | 一线/二线/三四线 | 最低工资红线、基准取值 |
| 成交周期档 cycleTier | 枚举 short/regular/midLong/long/ultraLong | 满产月数 9/12/15/18/24 | 爬坡曲线、前半年现金流 |
| 底薪 baseSalary | 数字（元/月） | | 现金流、红线、构成比 |
| 试用期月数 probationMonths | 数字 | | 前期现金流 |
| 试用期底薪系数 probationFactor | 0–1 | 试用期底薪打几折 | 前期现金流 |
| 提成率 commissionRate | 0–1 | | 提成计算 |
| **提成基数类型 commissionBase** | **枚举 回款/毛利/标价(GMV)** | **最大的坑，必选** | 折算真实提成 |
| 综合毛利率 marginRate | 0–1 | 基数是回款或标价时必填 | 折算真实提成 |
| 客单价 aov | 数字（元） | 单笔平均回款 | 单笔提成 |
| 月度目标/定额 quota | 数字（单数或金额） | HR 给的考核线 | 达标概率 |
| HR 画饼值 promisedMonthly | 数字（元/月，可选） | 「做得好月入 X」 | 打脸对比 |
| 社保公积金是否足额 socialFull | bool | | 隐性减薪 + 规范度信号 |

> 极简版可只留：城市档、成交周期档、底薪、提成率、提成基数、毛利率、客单价、定额、画饼值 —— 9 个字段，3 分钟填完。

### 4.2 输出清单

1. **冷静期望月收入**（稳定后）= 底薪 + 期望月提成
2. **达标概率**（定额是否虚高）
3. **前 6~12 个月现金流曲线**（底薪能不能撑过爬坡期）
4. **冷静 OTE 区间 vs HR 画饼值**（差距一眼看穿）
5. **红线报警清单**（见 4.4）
6. **综合判决**：🟢 值得去 / 🟡 有坑但可谈 / 🔴 慎重 + 一句话结论

### 4.3 核心公式（出处：算账器 v3.3 / 定价器 v2.5 / 招人器 v3.2）

**单笔提成（按提成基数类型分流）** —— 出处：算账器 `commission()`，口径 `提成 = 回款 × 毛利率 × 费率`
```
若 commissionBase = 回款:  单笔提成 = aov × commissionRate
若 commissionBase = 毛利:  单笔提成 = aov × marginRate × commissionRate
若 commissionBase = 标价:  单笔提成 = aov × commissionRate   （但需警示：标价≠到手）
```

**稳定期期望月提成**
```
期望月成交单数 mDeals = 达标单数 × 达标概率 P
期望月提成 = mDeals × 单笔提成
冷静期望月收入 = 底薪 + 期望月提成
```

**达标概率 P（定额虚高判定）** —— 出处：定价器「造假闸/attainability」
```
attainability = (定额折算的应达毛利) / (该城市该行业人均毛利基准 × p90 系数 1.8)
若 attainability > 1.3 → 定额虚高，P 低（画饼）
P 参考定价器菜单式：P(x) = clamp(0.47 + 0.75×(1 − attainability), 0.05, 0.95)
```

**前 N 月现金流（爬坡曲线）** —— 出处：招人器/算账器 `newHireYearRate` + `rampCurve12`
```
第 m 月期望提成 = 满产期望月提成 × rampCurve[cycleTier][m] / 100
第 m 月到手 ≈ 底薪(试用期打折) + 第 m 月期望提成
→ 画出前 12 个月曲线，标出「底薪撑不住」的月份
rampCurve 示例(short): [0,12,25,42,60,73,85,93,100,100,100,100]
（成交周期越长，前半年基本只有底薪）
```

**冷静 OTE 区间** —— 出处：定价器 OTE
```
OTE区间 = 达标月收入 × 12 × [1.5, 2.0]
对比：HR 画饼值 promisedMonthly —— 若 promised > OTE上限 → 画饼超标
```

### 4.4 红线规则（自动报警）

| 红线 | 判定 | 出处 |
|---|---|---|
| 底薪违法 | 底薪 < 当地最低工资（tier1 ¥2420 / tier2 ¥2000 / tier34 ¥1700） | 招人器 `minWageTable` |
| 试用期饿死 | 试用期底薪 × 试用期月数 撑不过爬坡期 | 爬坡曲线 |
| 提成注水陷阱 | commissionBase = 标价/GMV 且毛利率低 → 到手远低于表面 | 算账器折扣漏损逻辑 |
| **定额虚高逼造假** | attainability > 1.3 + 底薪低 → 逼你压货/造假（Wells Fargo 闸） | 定价器 W-20 |
| 长周期陷阱 | cycleTier ∈ {long, ultraLong} + 底薪低 → 前半年只有底薪 | 爬坡曲线 |
| 隐性减薪 | 社保不足额 → 到手缩水 + 公司不规范信号 | socialCostRate 0.30 |

### 4.5 综合判决口径
```
红线数 = 命中红线的条数
🔴 慎重:  ≥2 条红线  或  达标概率 < 20%
🟡 有坑:  1 条红线  或  冷静期望 < HR画饼值的 50%
🟢 值得:  0 红线 且 达标概率 ≥ 40% 且 前6月现金流不断
```

## 5. 模块② 选 —— 多 Offer 并排对比

- 用户录入 2~4 个 offer（每个走模块① 的输入），并排跑同一套算法。
- 对比维度：冷静期望月收入 / 达标概率 / 前 6 月现金流健康 / 红线数 / 综合分。
- 输出：**排序 + 每个 offer 的一句话点评**（"A 期望更高但定额虚高；B 稳但天花板低"）。
- 复用模块① 全部公式，零新增算法。

## 6. 模块③ 留 —— 该不该走 + 下家评估（你最独特的点）

### 6.1 输入
| 字段 | 说明 |
|---|---|
| 现公司现月收入 curMonthly | 实发 |
| 现公司稳定期期望 curExpected | 未来 12 个月大概 |
| 是否已有下家 offer hasNext | bool |
| 下家 offer（若有） | 走模块① 全套输入 |
| 预估空窗月数 idleMonths | 从离职到新工作到岗（裸辞时） |

### 6.2 核心公式（出处：留人器 流失价签 / 招人器 空窗价签）
```
走的代价（换工作的真实成本）:
  空窗损失 = curMonthly × idleMonths                       ← 你强调的核心：很多人不懂
  爬坡缺口 = Σ_{m=1..12} 新公司满产月收入 × (1 − ramp[m]/100)  ← 留人器 rampGap
  换工作总代价 = 空窗损失 + 爬坡缺口 + 找工作机会成本

留的代价（继续耗的机会成本）:
  若下家更好: 每多留 1 月损失 = 下家稳定月收入 − curMonthly
```

### 6.3 判决口径（防止裸辞踩坑）
```
无下家:
  🔴 强烈不建议裸辞，弹出「空窗损失 = ¥XX,XXX」的数字警示
  （把「从离职到找到工作的周期成本」量化给年轻人看）

有下家:
  跑模块① 评估下家 → 防止「逃出狼窝进虎口」
  下家综合分 ≤ 现公司 → 🟡 别急着走，下家未必更好
  下家明显更好 且 换工作总代价 < 半年收益差 → 🟢 值得走
```

**关键价值**：把「空窗期损失」和「下家到底行不行」两件年轻销售最容易低估的事，量化成数字摆在面前。

## 7. 基准数据策略（真正的护城河，也是最大的坑）

工具敢下判断，靠的是「这行业这城市的正常值是多少」。诚实处理：

- **首版**：内置一张**粗基准表**（城市档 × 成交周期档 → 人均年毛利、年流失率、满产月数），来源标注为「行业公开参考值」，**全部打「参考」角标**，数据不足显「—」。
- **诚实边界**：基准只用于「定额虚高」判定和现金流估算，**不谎称精确**。
- **护城河（二期）**：一旦验证有需求，把基准数据做成**可更新的数据文件/订阅**——这是抄不走的核心资产（对应你未来若转「薄后端」的升级点）。
- **「练」模块为什么砍掉**：个人手里没有任何销冠的真实数据，纯前端**蒸馏不出配方**。硬做只会变成假话术，违背铁律 2。二期可降级为「用你自己的数据做漏斗自诊断」（模块④ 干）。

```
顶部：品牌 + 授权署名 + 深色/浅色切换 + 免责入口
侧栏/底部 Tab（手机端折叠为底部 Tab）：
```

- **导出/打印**：`@media print` 生成 A4「Offer 冷静报告」，可截图分享（隐藏敏感薪资可选）。
- **离线**：从 `file://` 直接双击打开即可用，零安装。

## 11. 防盗版立场（已选纯前端，这里说清楚现实）

- **物理事实**：纯前端 + 单文件 + 离线 = **技术上无法防复制**。企业版自己的结论就是「社会防护 > 技术防护，到期只降级不锁数据」。
- **本方案采取的策略**：
  1. **低价**（9.9~128）——没人费劲破解一杯奶茶钱的东西，靠量。
  2. **署名 + 授权名**（社会防护）：报告页 + 打印页脚显示购买者授权名，转发出去带着别人的名字。
  3. **价值放在「持续更新的基准数据 + 内容社群」**，而非一次性文件本身——文件会过时，服务不会。
  4. **护城河留在二期**：真要防白嫖，就把基准数据搬到薄后端按账号发放（届时牺牲「纯前端」，是明确的升级路径，不是现在做）。
- **明确不做**：一机一码/离线 ECDSA 对单文件基本无效（拿到 full 文件即全解锁），MVP 不浪费精力。

## 12. 法律与风控（必须内置）

1. **免责声明**（固定底部）：「本工具为决策参考，不构成职业建议，不承诺任何收入。」
2. **绝不做公司黑名单/点名评价库**——只算用户自己输入的数字（名誉侵权红线）。
3. **数据只在本机**，不采集用户薪资到服务器（隐私卖点 + 免责）。
4. **基准数据全部标「参考值」**，不谎称精确。
