# 发码云函数 · 部署与使用（5 分钟）

零依赖，只要服务器上有 **Node.js（≥ 14）** 就能跑，不用 `npm install`。

## 1. 上传 & 改口令

把 `server/` 这个目录传到你的服务器（比如 `/opt/dx-famaqi/`）。**上线前必须改三样**（在 `ecosystem.config.js` 里，或用系统环境变量注入）：

| 变量 | 作用 | 必须改 |
|---|---|---|
| `DX_SECRET` | 暗号，**必须和定薪器 `ACT_SECRETS` 里当前那个、以及发码器的暗号完全一致** | 用你自己的 |
| `DX_ADMIN_PW` | 后台口令（看订单 / 下备份 / 手动发码） | ✅ |
| `DX_ISSUE_TOKEN` | 签发口令（支付回调自动发码时带上） | ✅ |
| `DX_MAX_REISSUE` | 每单允许自助换机次数（默认 3） | 可选 |
| `DX_NOTIFY_URL` | 新订单推送（server酱/企业微信机器人），填了才推 | 可选 |

## 2. 用 pm2 跑起来（崩了自动起 + 开机自启）

```bash
npm i -g pm2                     # 只装一次
cd /opt/dx-famaqi
pm2 start ecosystem.config.js    # ① 启动，崩溃自动拉起
pm2 startup                      # ② 生成开机自启脚本，按它输出的那行命令粘贴执行
pm2 save                         # ③ 保存当前进程列表，重启后照此恢复
```

到这里：**进程崩 → 自动起；服务器重启 → 自动起**。看状态 `pm2 status`，看日志 `pm2 logs dx-famaqi`。

> 建议再用 Nginx 把 `https://你的域名` 反代到 `127.0.0.1:8787`，并只对 `/admin*` 加 IP 白名单。纯 HTTP 也能跑（激活算法不依赖 https）。

## 3. 三个入口

- **客户换机/重激活页**：`https://你的域名/`（或 `/reactivate`）— 客户输订单号 + 新设备码，自助领新锁机码，限次。
- **后台**：`https://你的域名/admin?pw=你的ADMIN口令` — 看所有订单、手动发码、下载备份。
- **自动发码接口**：让你的支付平台「发货 webhook」`POST` 到
  ```
  POST /api/issue
  Header: x-issue-token: 你的ISSUE口令
  Body:   {"orderId":"平台订单号","mode":"G","buyer":"微信名/备注"}
  ```
  返回 `{"ok":true,"code":"DX-G-..."}`，把 code 发给买家即可。`mode:"D"` 则需带 `"device":"12位设备码"`（锁机码，适合按座）。同一订单号重复调用返回同一个码，不会重复发。

## 4. 每周备份（一条命令）

订单只写进 `orders.jsonl`（追加、永不覆盖）。每周拉回本地存一份：

```bash
scp 用户@你的服务器:/opt/dx-famaqi/orders.jsonl ~/backup/orders-$(date +%F).jsonl
```

或直接浏览器点后台页的「⬇ 下载订单备份」。（可选：填了 `DX_NOTIFY_URL` 后，每笔新订单还会推你一条，文件坏了也有据可查。）

## 5. 和离线兜底的关系

云函数挂了**不影响已激活的老用户**（激活是本地离线验的）。最坏情况只是「新买家要等你手动发码」——这时打开本地 `hr-famaqi.html` 手动出码即可，业务不断。云函数是「自动发货机 + 自助换机」，本地发码器是它的兜底。

## 6. 将来换暗号（平滑，不断老客户）

想换新暗号时：
1. 定薪器 `ACT_SECRETS` 数组里，把**新暗号加到最前**，老暗号留在后面（新老码都认）。
2. 服务器 `DX_SECRET` 改成**新暗号**（之后新发的码用新暗号）。
3. 老客户手里的老文件+老码继续有效；他们升级到新文件后，因为新文件同时认老暗号，也不断码。
