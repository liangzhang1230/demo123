### 2.2 企业版同式规则(公式口径,禁止改动)

| 规则 | 公式(企业版账单A同式) |
|---|---|
| 底薪矩阵 | B(层,档) = round(CITY_BASE[城] × LV_MULT[层][档] × CYCLE_F[周期]),四舍五入到**元** |
| 收入拆分 | 达标收入 T = 现金 90% + 长期分红池 10%;现金目标 = 0.9×T,分红池 = 0.1×T(企业版账单A:底薪:提成缺口:长期分红池) |
| 提成回算 | 现金浮动 gap = 0.9×T − B;**提成率(毛利口径)r_ml = gap ÷ 月毛利 G**;等效回款提成率 r_hk = gap ÷ 月回款 |
| 吃穿线 W-02 | B ≥ 0.9×T → 该档作废:「这不是方案,是固定工资」 |
| 饥饿线 W-03 | B < B(层,0)(预警档底薪)→ 红:饥饿-鱼饵警报 |
| 鱼饵线 W-04 | gap/T ≥ 0.65 → 黄:浮动占比贴着鱼饵线 |
| 最低工资 W-29 | B < MINWAGE[城] → 红:底薪疑似违法 |
| 好招指数 | goodHire = min( B ÷ B(层,0), T设计 ÷ T(层,0) )(企业版公式;HR 版 T设计=满产月现金 FULL) |

## 3. 输入字段规格

### 3.1 首屏(基本盘,6 项)

| # | id | 标签 | 控件 | 选项/范围 | 默认 | hint(原文照用) |
|---|---|---|---|---|---|---|
| 1 | industry | 行业 | 分段 | 通用/教培/装修建材/企业服务 | 通用 | 选行业自动带入常见提成率,可再改 |
| 2 | city | 城市 | 分段 | 一线/二线新一线/三四线 | 必选无默认 | — |
| 3 | layer | 岗位层级 | 分段 | 销售/主管/总监高管 | 销售 | 定薪三档会给出该层级初/中/高三档方案 |
| 4 | targetHK | 这个岗一个月该做多少回款(元) | 数字 | 0~99,999,999 | 300000 | 老板对这个岗位的月回款期望,张口就能说的那个数 |
| 5 | budgetBase | 预算底薪(元/月) | 数字 | 0~999,999 | 6000 | 你现在打算给的底薪 |
| 6 | baseType | 底薪性质 | 分段 | 无责/有责/零底薪 | 无责 | 「有责底薪」在候选人眼里不是安全底,等于没有 |

### 3.2 折叠区「展开精算 ▾」(6 项)

| # | id | 标签 | 控件 | 选项/范围 | 默认 | hint |
|---|---|---|---|---|---|---|
| 7 | rate | 提成率(%) | 数字 | 0~100 步长0.1 | 随行业包 | — |
| 8 | commBase | 提成基数 | 分段 | 按回款/按毛利/按标价 | 按回款 | 「按毛利」时名义提成率会被毛利率打折——候选人最容易翻脸的一条 |
| 9 | margin | 综合毛利率(%) | 数字 | 1~95 | 随行业包 | **仅 commBase=按毛利 时显示**;其他基数下负担率静默用行业默认毛利率 |
| 10 | cycle | 成交周期 | 分段 | 短周期(≤30天)/常规(1–3月)/中长(4–6月)/长(7–12月)/超长(>12月) | 常规 | 周期越长底薪越厚(底薪矩阵自动按周期加成)——档位与企业版 cycleTier 完全一致 |
| 11 | lead | 线索从哪来 | 分段 | 公司给/一半一半/纯自己找 | 一半一半 | 纯冷启动岗位属开拓型任务,常规提成方案不适用(企业版 W-24)。本字段只驱动坑检测,不参与计算 |
| 12 | promised | 打算在 JD/面试里说的「做得好月入」(元) | 数字 | 0~9,999,999 | 空可不填 | 不填则跳过画饼检测 |

### 3.3 校验

targetHK 为 0/空:结果区只显示「先填月回款目标,其他都算不出来」,无 NaN;budgetBase 空按 0;输入即重算(oninput→recalc)。

**取整纪律:所有红黄绿判定(负担带、鱼饵线、好招灯)一律用未取整的原始值比较,只在显示时才四舍五入**——否则边界值(如负担率 25.95%)会因先取整而误判。

layer=主管/总监高管时,targetHK 字段 hint 追加一句:「主管/高管请填其分管团队的月回款目标(企业版同口径)」。

## 4. 计算引擎(严格按此顺序与取整)

### 4.1 基础量

```
cf = CYCLE_F[cycle]
B(i) = round( CITY_BASE[city] × LV_MULT[layer][i] × cf )        // 元取整,企业版 roundYuanFen 同义
T(i) = BENCH[city][layer][i]
Bwarn = B(0);Twarn = T(0)                                        // 预警档
margin_used = (commBase==='按毛利') ? margin : 行业包默认毛利率
月毛利 G = targetHK × margin_used/100
effRate = (commBase==='按毛利') ? rate×margin/100 : rate          // 占回款的等效名义率(按标价不折算,同筛选器)
```

### 4.2 现有方案体检(用户填的 budgetBase/rate)

```
满产月提成 FULL_COMM = targetHK × effRate/100
满产月现金 FULL     = budgetBase + FULL_COMM
好招指数 goodHire   = min( budgetBase÷Bwarn , FULL÷Twarn )        // 企业版公式,2位小数
安全底 safeFloor    = (无责) ? budgetBase : 0                     // 有责/零底薪 = 0,同筛选器引擎
候选人冷静月收入 CALM = safeFloor + FULL_COMM × ATTAIN(0.47)       // 整数元;纯企业版口径(全球真实达标率 43–51% 中值),不乘其他折减
浮动占比 floatShare = FULL_COMM ÷ FULL
现方案负担率 = FULL_COMM ÷ G                                      // 百分数,1位小数
```

goodHire 灯:≥1.15 绿「好招:底薪和满产都在行情预警线之上有余量」;1.00~1.15 黄「贴着预警线,能招但谈薪会被压」;<1.00 红「难招:低于行情预警线,聪明的候选人算完就不来了」。

### 4.3 定薪三档(企业版档位制回算,对 i ∈ {1初级,2中级,3高级})

```
① 建议底薪 SB_i = B(i)                                  // 元取整,不再另取整到百
② 长期分红池 L_i = 0.10 × T(i)                          // 年兑,单列展示;建议书中必须表述为独立年度奖金/分红池,严禁表述为扣发提成
③ 现金浮动 gap_i = 0.90 × T(i) − SB_i
   若 gap_i ≤ 0 → 该档标记 W-02 作废:「底薪吃穿现金目标——这不是方案,是固定工资」
④ 建议提成率(回款口径,主显) r_hk = gap_i ÷ targetHK ×100    // 0.1%
   建议提成率(毛利口径,小字) r_ml = gap_i ÷ G ×100           // 0.1%
⑤ 单岗负担率 = gap_i ÷ G ×100                            // 0.1%
   < 18「偏低——鱼饵不香,好手不来(W-06 同义)」黄
   18~26「健康」绿
   > 26「偏高——这个回款目标撑不起这套薪酬(W-05 同义)」红
⑥ 每档附加检查:SB_i<MINWAGE→W-29 红;gap_i/T(i)≥0.65→W-04 黄
```

三档表每行点评用企业版 GRADE_DESC 原文;**推荐档=初级(有效)**(企业版原文:多数团队按这档定薪)。

### 4.4 坑检测(现有方案;编码对齐企业版 W 系)

| # | 触发条件 | 坑名 | 文案 |
|---|---|---|---|
| K-W29 | 无责 且 0<budgetBase<MINWAGE | 底薪疑似违法 | ¥{budgetBase} 低于该城市最低工资参考 ¥{MINWAGE}——员工可追讨差额并申请劳动仲裁(企业版 W-29 同义) |
| K-W03 | budgetBase < Bwarn | 饥饿-鱼饵 | 底薪压到预警线(¥{Bwarn})以下——你不是在激励销售,是在制造一个必然作弊的人(企业版 W-03 原文) |
| K-W02 | budgetBase ≥ 0.9×FULL | 固定工资化 | 底薪吃穿现金目标——提成没有存在感,干多干少一个样(企业版 W-02 同义) |
| K-W04 | floatShare ≥ 0.65 | 鱼饵线 | 浮动占比 {floatShare}% 已贴着鱼饵线 65%——短周期可用,但请确认底薪足以生存(企业版 W-04 同义) |
| K-W0506 | 现方案负担率出 18~26 带 | 负担出带 | 偏低:「鱼饵不香,好手不来」/ 偏高:「这个回款撑不起这套薪酬,团队长大会把你撑穿」 |
| K-有责 | baseType=有责 | 有责底薪坑 | 候选人会把有责底薪当零看——它不是安全底。你以为给了 ¥{budgetBase},他心里记的是 ¥0 |
| K-零底 | baseType=零底薪 | 零底薪坑 | 零底薪只筛得出两种人:走投无路的,和路子太野的 |
| K-毛利 | commBase=按毛利 | 毛利提成幻觉 | 名义 {rate}%,按 {margin}% 毛利折算,等效回款提成只有 {rate×margin/100,1位小数}%——候选人入职后发现这条,是翻脸率最高的坑 |
| K-画饼 | promised 已填 且 promised > T(3) | 画饼超标 | 你打算说月入 ¥{promised},已超过该城市该层级「领先档达标线」¥{T(3)}——头部标杆才拿这个数,饼太大会反噬信任 |
| K-裸奔 | lead=纯自己找 | 线索裸奔 | 不给线索 = 拿人家的头三个月做免费市场测试,爬坡期流失率翻倍。开拓型岗位请按企业版 W-24 处理:保底期底薪不挂业绩+里程碑奖三档+季度结算,禁用月结提成 |

命中 N 条 →「⚠ 有 N 个坑会被聪明的候选人当面问穿」;0 条 →「✓ 未发现结构性坑」。

### 5.3 定薪工作台(输入结果同屏)
1. 吸顶摘要条:`好招指数 {goodHire}{灯} · 候选人冷静折算 ¥{CALM} · 坑 {N} 个`
